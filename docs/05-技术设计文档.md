# 技术设计文档

## 1. 技术选型（均为当前主流方案）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 构建 | Vite 5 | 主流、冷启动快、TS 原生支持 |
| 框架 | React 18 + TypeScript 5（strict） | 生态最大；strict 保证工程质量 |
| 状态 | Zustand 5 | 轻量无样板；`subscribe` 天然对接持久化 |
| 图谱 | D3 v7（selection/force/drag/zoom/scale） | 用户指定；图形控制力最强 |
| 导出 | docx 9（DOCX）、JSZip 3（EPUB）、原生 Blob（TXT/MD/JSON） | 纯浏览器端生成 |
| UI | 自研组件库（Resonance HUD 深色金调：CSS Tokens + 纯直角 + 发丝金边） | 参考稿风格无现成库可覆盖；组件数量可控 |
| 其他 | nanoid（ID）、原生 Fetch（REST/AI） | 零冗余依赖 |
| 桌面 | Electron 44 + electron-builder 26（NSIS/portable） | 本机文件存储 + 本地文件夹读写同步 + 无边框窗控 |
| 文件系统 | File System Access API（`showDirectoryPicker`）+ `webkitdirectory` 回退 | 整个工作区目录的递归读与直写落盘（Chromium/Electron） |

**不用**：UI 组件库（AntD/MUI 视觉不符且体积大）、react-router（内部 hash 路由 10 行解决）、Redux（该规模 Zustand 足够）。

## 2. 分层架构

```
┌─ features/        页面层（dashboard/writing/characters/graph/events/timeline/
│                   locations/factions/items/atlas/docs/export/settings）
├─ components/ui/   自研组件库（Modal/EntityPicker/Radar/Toast…）
├─ store/           Zustand：projectStore(数据+CRUD+自动保存+文档层) / uiStore(路由/Toast)
├─ core/            领域逻辑（无 React 依赖，可单测）
│   ├─ types.ts         数据模型（唯一事实源，含 ProjectDoc/Volume）
│   ├─ desktop.ts       桌面/Web 能力检测（isDesktop / 桌面数据桥）
│   ├─ consistency.ts   一致性引擎（提及识别/未登记词探测/体检）
│   ├─ collections.ts   实体集合/标签工具    ├─ fuzzy.ts  相似度
│   ├─ contextPack.ts   上下文包生成
│   ├─ docs/            工作区文档：markdown.ts 分块解析 / classify.ts 归类
│   ├─ import/          aiImport(上下文包回导+分卷) / agentImport(SOUL)
│   ├─ export/          txt/md/docx/epub/backup + aiExport(AI 上下文包/工作区直写)
│   ├─ storage/         StorageAdapter 接口 + 四个实现（indexeddb/localstorage/rest/desktop）
│   └─ seed.ts          示例作品《九州烟云》
└─ styles/          tokens.css / base.css / components.css / pages.css
```

依赖方向：`features → components/ui → store → core`，禁止反向。

## 3. 数据模型（摘要，完整见 `core/types.ts`）

```ts
interface Project {
  id: string; name: string; genre: string; description: string;
  createdAt: number; updatedAt: number;
  characters: Character[]; relations: Relation[];
  events: StoryEvent[]; items: Item[];
  locations: LocationNode[]; factions: Faction[];
  chapters: Chapter[];
  volumes?: Volume[];              // 分卷按全书章号区间划定（startOrder–endOrder）
  docs?: ProjectDoc[];             // 工作区文档层（无损往返）
  ignoreWords: string[];           // 未登记名词忽略词表
  settings: ProjectSettings;       // AI 接口预留配置
}
```

- 所有实体继承 `BaseEntity { id, name, aliases[], description, tags[], createdAt, updatedAt }`。
- **引用一律存 ID**（`factionId / ownerId / participantIds / causeIds / effectIds …`），展示层再反查——这是图谱一致性的数据基础。
- 人物形象 = 256px 内 base64（上传时 canvas 压缩），IndexedDB 容量优先。
- 事件 `sortIndex:number` 驱动时间线/轨迹/事件图谱横轴；`timeLabel:string` 供阅读。
- **工作区文档层** `ProjectDoc { id, path, category, content, updatedAt }`：`path` 为相对工作区根、正斜杠；`category: 'setting'|'ledger'|'reports'|'promo'|'guide'|'tool'|'other'` 由路径顶层目录推导；`content` 存原文全文（唯一事实源）。因 `buildBundle` 直接序列化整个 `project`，`docs` 随 `novel-context.json` 与 JSON 备份自动落盘，往返无损。

## 4. 一致性引擎（`core/consistency.ts`）

```
输入 text
 ├─ collectMentions()      对每个实体的 name+aliases 做子串扫描 → 已登记提及(带位置/实体类型)
 └─ detectUnknownNames()   未登记名词探测:
      1. 正则切 2–4 字 CJK 滑窗, 统计词频
      2. 过滤: 停用词表(内置常见词~300) ∪ 已登记名/别名的子串 ∪ ignoreWords ∪ 单字
      3. 词频≥2 保留, 按频次排序 → Candidate[]
      4. 对每个 Candidate 用 fuzzy 对全部实体名求相似度, ≥0.6 输出 "疑似想写: xx (82%)"
auditProject()            全项目体检:
      悬空引用(所有 ID 字段逐一校验)
      别名冲突(同别名映射到多实体)
      因果时序(cause.sortIndex > effect.sortIndex)
      近名提醒(实体两两相似度≥0.8, n<200 时 O(n²) 可接受)
```

性能：写作台输入经 300ms 防抖后计算；10 万字内提及扫描为 O(实体数×文本长) 的 `indexOf` 循环，毫秒级。

## 5. 存储层（`core/storage/`）

- `StorageAdapter` 接口见 PRD §6.1；实现：`DesktopAdapter`（桌面端默认，经 `window.moshuDesktop.dataStorage` 把作品 JSON 落本机文件，目录可选）、`IndexedDBAdapter`（Web 默认，库 `novel-atlas`/store `projects`）、`LocalStorageAdapter`（键 `novel-atlas:project:{id}`）、`RestStorageAdapter`（PRD §6.2 契约）。
- `core/desktop.ts` 的 `isDesktop()` 判端：`createAdapter` 在桌面用 `desktop`、Web 下自动回退 `indexeddb`；本地文件夹直写/同步另需 `supportsDirectoryExport()`（File System Access API），网页版相应功能置灰。
- 选择器在设置页切换，适配器 ID 存 `localStorage('novel-atlas:app')`。
- projectStore 每次变更后 800ms 防抖 `saveProject`（自动保存）；保存状态徽标反馈。
- 图片体积大 → 提示优先用 IndexedDB；REST 模式下同样的 JSON 原样 PUT。

## 6. D3 图谱实现要点（`features/graph/`）

- 通用底座：一个 `useD3Force` 封装（selection + forceSimulation + drag + zoom），视图只传 nodes/links/着色器/点击回调。
- **关系图谱**：`forceManyBody/-60` + `forceLink(distance 按强度反比)` + `forceCollide(r+8)`；节点 r = 14 + 度数×2（上限 34）；势力色填充，主角金环、已故灰环；边宽 = 1 + 强度。
- **事件图谱**：`forceX(时间序归一化坐标)` 固定横轴 + 弱化 y 向斥力 → 天然"左古右今"因果网；因果边带箭头（marker）。
- **人物轨迹**：非力导向；scaleLinear 横轴 + 事件节点交替上下布点 + 折线连接 + 地点标注。
- 缩放/拖拽/悬停高亮邻居为三个视图共用行为。

## 7. 导出管线（`core/export/`）

- `txt/md`：字符串拼装 → Blob 下载（统一 `downloadBlob` 工具）。
- `docx`：`docx` 库 Document/Heading/Paragraph；设定集附录按实体类型分节。
- `epub`：JSZip 组 EPUB3（mimetype STORE + container.xml + content.opf + nav.xhtml + 章节 xhtml，正文按空行分段落 `<p>`，HTML 转义）。
- `json`：全项目序列化（备份）；导入走 `JSON.parse` + 结构校验 + `replaceProject`。
- `AI 上下文包`（`core/export/aiExport.ts`）：产出与写作工作区同构的文件树（`<书名>-ai-context/` + `正文/卷NN/` + `agents/` + 工作区文档），详见 §8。

## 8. 工作区文档 / 文件夹导入 / 本地同步

把应用从"只装结构化数据"升级为"承载整个写作工作区"，并为桌面端提供与外部工具协同的双向同步。

- **分块解析 `core/docs/markdown.ts`**：`parseMarkdown(text) → MdBlock[]`（标题/引用/GFM 管道表格/列表/代码/段落），表格单元格 `｜→|` 与 `aiExport` 的 `|→｜` 转义口径对称；零依赖、不引第三方 markdown 库。
- **归类器 `core/docs/classify.ts`**：`classifyWorkspace({path,text}[])` 按路径分桶（bundle / 逐章 / 合并稿 / SOUL / docs / skipped），`categoryOf(path)` 推分类，`isTextPath` 白名单跳二进制；纯函数、零 DOM。
- **回导 `core/import/aiImport.ts`**：`parseContextBundle`（JSON → 归一化 `Project`，含 `docs`/`volumes`）；`applyChapterFiles` 按文件名 `第NNN章` 全局章号升序 + 卷目录自动建卷（修复"乱序选择致章节错乱"）；`applyVolumes` 合并整卷合稿；`normalizeProject` 对 `docs` 补 id/推 category。
- **导出落盘 `core/export/aiExport.ts`**：`buildWorkspaceFiles` 产出工作区文件树，末尾按 `project.docs[].path` **原样回写**文档（生成侧 path 优先去重）；`writeWorkspaceToDirectory`（FS Access 直写，只增改不删）/ `exportAiContextZip`（ZIP 回退）/ `readWorkspaceDir`（递归读目录文本文件，跳过 `.writing/node_modules` 与二进制）。
- **文件夹一键导入（`features/export/ExportPage.tsx`）**：`pickSourceDirectory`/`showDirectoryPicker` 主路径 + `<input webkitdirectory>` 回退 → `classifyWorkspace` → `assembleWorkspace` 组装 `Project` + 智能体种子 → 汇总卡 → 「为新 / 覆盖」（模块级 `assembleWorkspace` 供导入与同步复用）。
- **文档页（`features/docs/`）**：`DocsPage.tsx` 左分类树右「语义视图 / 编辑原文」（编辑走 `useDebouncedValue` + `upsertDoc` 300ms 自动保存）；`render.tsx` 按 `path/category` 命中语义适配器（伏笔台账 / 人物状态表 / 巡检报告 / 设定），未命中回落 `MarkdownView`，脚本/JSON 走等宽原文；语义视图只读、人物名可 `openDetail` 跳图谱。
- **本地双向同步（`ExportPage`，仅桌面端）**：以内容基线 `Record<path,content>` diff 区分"外部改动" vs "自写"，避免回环；防抖推送 `pushWorkspace` + 轮询拉取 `pullWorkspace`（均经 `useProjectStore.getState()` 取最新态，异步锁 `busyRef` 防重叠）；`isDesktop() && supportsDirectoryExport()` 双门控，网页版整块禁用。

## 9. 质量约定（对标开源组件库）

- TS strict 全开；领域类型零 `any`；UI 层受控组件。
- 命名：组件 PascalCase、hook `useXxx`、领域函数 camelCase；文件与目录 kebab/同名。
- 组件单一职责；跨页复用（EntityPicker/卡片/表单）一律下沉 `components/ui`。
- 危险操作（删除/清空/恢复）一律二次确认；所有列表空态有引导。
- 提交前验收：`tsc --noEmit` + `vite build` 零错误。
