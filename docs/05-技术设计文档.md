# 技术设计文档

## 1. 技术选型（均为当前主流方案）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 构建 | Vite 5 | 主流、冷启动快、TS 原生支持 |
| 框架 | React 18 + TypeScript 5（strict） | 生态最大；strict 保证工程质量 |
| 状态 | Zustand 5 | 轻量无样板；`subscribe` 天然对接持久化 |
| 图谱 | D3 v7（selection/force/drag/zoom/scale） | 用户指定；图形控制力最强 |
| 导出 | docx 9（DOCX）、JSZip 3（EPUB）、原生 Blob（TXT/MD/JSON） | 纯浏览器端生成 |
| UI | 自研组件库（CSS Tokens + 玻璃拟态） | 参考稿风格无现成库可覆盖；组件数量可控 |
| 其他 | nanoid（ID）、原生 Fetch（REST/AI） | 零冗余依赖 |

**不用**：UI 组件库（AntD/MUI 视觉不符且体积大）、react-router（内部 hash 路由 10 行解决）、Redux（该规模 Zustand 足够）。

## 2. 分层架构

```
┌─ features/        页面层（dashboard/writing/characters/events/items/
│                   locations/factions/timeline/graph/export/settings）
├─ components/ui/   自研组件库（Modal/EntityPicker/Radar/Toast…）
├─ store/           Zustand：projectStore(数据+CRUD+自动保存) / uiStore(路由/Toast)
├─ core/            领域逻辑（无 React 依赖，可单测）
│   ├─ types.ts         数据模型（唯一事实源）
│   ├─ consistency.ts   一致性引擎（提及识别/未登记词探测/体检）
│   ├─ fuzzy.ts         相似度（Levenshtein 归一化）
│   ├─ contextPack.ts   上下文包生成
│   ├─ export/          txt/md/docx/epub/backup
│   ├─ storage/         StorageAdapter 接口 + 三个实现
│   └─ seed.ts          示例作品《九州烟云》
└─ styles/          tokens.css / base.css / components.css
```

依赖方向：`features → components/ui → store → core`，禁止反向。

## 3. 数据模型（摘要，完整见 `core/types.ts`）

```ts
interface Project {
  id: string; name: string; genre: string; description: string;
  createdAt: number; updatedAt: number;
  characters: Character[]; relations: Relation[];
  events: StoryEvent[]; items: Item[];
  locations: LocationNode[]; factions: Faction[];
  chapters: Chapter[];
  ignoreWords: string[];           // 未登记名词忽略词表
  settings: ProjectSettings;       // AI 接口预留配置
}
```

- 所有实体继承 `BaseEntity { id, name, aliases[], description, tags[], createdAt, updatedAt }`。
- **引用一律存 ID**（`factionId / ownerId / participantIds / causeIds / effectIds …`），展示层再反查——这是图谱一致性的数据基础。
- 人物形象 = 256px 内 base64（上传时 canvas 压缩），IndexedDB 容量优先。
- 事件 `sortIndex:number` 驱动时间线/轨迹/事件图谱横轴；`timeLabel:string` 供阅读。

## 4. 一致性引擎（`core/consistency.ts`）

```
输入 text
 ├─ collectMentions()      对每个实体的 name+aliases 做子串扫描 → 已登记提及(带位置/实体类型)
 └─ detectUnknownNames()   未登记名词探测:
      1. 正则切 2–4 字 CJK 滑窗, 统计词频
      2. 过滤: 停用词表(内置常见词~300) ∪ 已登记名/别名的子串 ∪ ignoreWords ∪ 单字
      3. 词频≥2 保留, 按频次排序 → Candidate[]
      4. 对每个 Candidate 用 fuzzy 对全部实体名求相似度, ≥0.6 输出 "疑似想写: xx (82%)"
auditProject()            全项目体检:
      悬空引用(所有 ID 字段逐一校验)
      别名冲突(同别名映射到多实体)
      因果时序(cause.sortIndex > effect.sortIndex)
      近名提醒(实体两两相似度≥0.8, n<200 时 O(n²) 可接受)
```

性能：写作台输入经 300ms 防抖后计算；10 万字内提及扫描为 O(实体数×文本长) 的 `indexOf` 循环，毫秒级。

## 5. 存储层（`core/storage/`）

- `StorageAdapter` 接口见 PRD §6.1；实现：`IndexedDBAdapter`（默认，库 `novel-atlas`/store `projects`）、`LocalStorageAdapter`（键 `novel-atlas:project:{id}`）、`RestStorageAdapter`（PRD §6.2 契约）。
- 选择器在设置页切换，适配器 ID 存 `localStorage('novel-atlas:app')`。
- projectStore 每次变更后 800ms 防抖 `saveProject`（自动保存）；保存状态徽标反馈。
- 图片体积大 → 提示优先用 IndexedDB；REST 模式下同样的 JSON 原样 PUT。

## 6. D3 图谱实现要点（`features/graph/`）

- 通用底座：一个 `useD3Force` 封装（selection + forceSimulation + drag + zoom），视图只传 nodes/links/着色器/点击回调。
- **关系图谱**：`forceManyBody/-60` + `forceLink(distance 按强度反比)` + `forceCollide(r+8)`；节点 r = 14 + 度数×2（上限 34）；势力色填充，主角金环、已故灰环；边宽 = 1 + 强度。
- **事件图谱**：`forceX(时间序归一化坐标)` 固定横轴 + 弱化 y 向斥力 → 天然"左古右今"因果网；因果边带箭头（marker）。
- **人物轨迹**：非力导向；scaleLinear 横轴 + 事件节点交替上下布点 + 折线连接 + 地点标注。
- 缩放/拖拽/悬停高亮邻居为三个视图共用行为。

## 7. 导出管线（`core/export/`）

- `txt/md`：字符串拼装 → Blob 下载（统一 `downloadBlob` 工具）。
- `docx`：`docx` 库 Document/Heading/Paragraph；设定集附录按实体类型分节。
- `epub`：JSZip 组 EPUB3（mimetype STORE + container.xml + content.opf + nav.xhtml + 章节 xhtml，正文按空行分段落 `<p>`，HTML 转义）。
- `json`：全项目序列化（备份）；导入走 `JSON.parse` + 结构校验 + `replaceProject`。

## 8. 质量约定（对标开源组件库）

- TS strict 全开；领域类型零 `any`；UI 层受控组件。
- 命名：组件 PascalCase、hook `useXxx`、领域函数 camelCase；文件与目录 kebab/同名。
- 组件单一职责；跨页复用（EntityPicker/卡片/表单）一律下沉 `components/ui`。
- 危险操作（删除/清空/恢复）一律二次确认；所有列表空态有引导。
- 提交前验收：`tsc --noEmit` + `vite build` 零错误。
