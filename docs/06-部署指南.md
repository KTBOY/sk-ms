# 06 · 部署指南

项目为纯前端 SPA，`dist/` 即全部产物，可托管到任何静态站点服务。

## GitHub Pages（已配置自动发布）

仓库已包含 `.github/workflows/deploy-pages.yml`：推送到 `main` 分支即自动构建并发布到 Pages。

首次部署步骤：

1. 在 GitHub 上新建一个仓库（如 `novel-atlas`，公开）。
2. 本地执行：
   ```bash
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```
3. 打开仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
4. 稍等 Actions 跑完，访问 `https://<你的用户名>.github.io/<仓库名>/`。

之后每次 `git push` 都会自动重新发布。

> 说明：应用无前端路由（页内 Tab 切换），vite `base: './'` 相对路径同时兼容 Pages 子路径与 Electron `file://` 加载，无需改动。仓库中不含任何密钥；AI 接口配置只存在访问者浏览器本地。

## 其他静态托管（Vercel / Netlify / Cloudflare Pages）

- 构建命令：`npm run build`
- 产物目录：`dist`
- 无需其他配置（根路径部署，`base: './'` 同样可用）

## Electron 桌面应用

```bash
npm run app:build   # 产出 release/ 下的 NSIS 安装包与便携版
```

> 打包时需从 GitHub 下载 Electron 运行时，若超时/连接重置，走镜像：
> `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npx electron-builder --win`

### NSIS 安装向导（标准多步流程）

安装包为**辅助式向导**（非一键安装），遵循 Windows 桌面软件的常规安装体验：

1. **欢迎页** —— 品牌侧栏（HUD 深色金调）+ 欢迎Copy
2. **安装模式** —— 为我安装（默认，无需管理员）/ 为所有用户安装
3. **附加任务** —— 桌面快捷方式 / 开始菜单快捷方式（默认勾选）
4. **安装位置** —— 默认 `%LOCALAPPDATA%\Programs\墨枢NovelAtlas`，可**浏览并修改任意安装目录**
5. **完成页** —— 「运行 墨枢NovelAtlas」勾选框（默认勾选），点击完成即启动软件

向导界面为简体中文；卸载程序复用同一套品牌侧栏。相关配置在 `package.json` 的 `build.nsis` 段。

### 启动性能（路由级代码分割）

启动慢的根因是单包 825KB（全量含 D3 / docx / jszip）在首屏前解析执行。现已拆分：

- **首屏只加载入口包（约 206KB）**：React + 总览页 + 应用壳；
- 其余 10 个页面 `React.lazy` 按需加载（`src/App.tsx`），首帧渲染后在空闲时段自动预取全部分块（`usePrefetchPages`），页内切换无加载感；
- `docx` / `jszip` 体积大，改为**点击导出时才动态 `import()`**（`docxExport` / `epubExport` / `aiExport`），只在真正导出时加载。

实测（同一台机器热启动，`MOSHU_BOOT_LOG=1` 开启计时）：主窗口可见 **6.2s → 0.65s**。

启动各阶段耗时埋点已内置于 `electron/main.cjs`（`bootLog`），设环境变量 `MOSHU_BOOT_LOG=1` 启动可写 `%TEMP%/moshu-boot.log`（whenReady / splash / did-finish-load / 首帧 +2rAF / 撤 splash），用于回归排查。

### 桌面端无边框窗口（融合式标题栏）

Windows 安装版 / 便携版为**无边框窗口**：原生标题栏移除，顶栏兼作标题栏——

- 顶栏空白处可**拖拽移动窗口**，双击可最大化/还原；
- 右上角内嵌 **最小化 / 最大化（还原）/ 关闭** 按钮（关闭悬停红，与原生标题栏心智一致，样式同 flash-edit）；
- 实现链路：`electron/main.cjs`（`frame: false` + 窗口控制 IPC）→ `electron/preload.cjs`（白名单桥 `window.moshuDesktop`）→ `src/components/layout/WindowControls.tsx`（仅桌面端挂载）。

**Web 端完全不受影响**：浏览器无 preload 桥，渲染层不挂载窗控按钮，拖拽区样式全部限定在 `html.is-desktop` 作用域内（`src/main.tsx` 检测桥存在才添加该类）。

### 桌面端数据存放（本机文件存储，目录可选）

桌面端作品数据以 **JSON 文件**落盘（`<数据目录>/projects/<作品id>.json`），不经任何服务器；设置页可**更改存放位置 / 打开文件夹 / 恢复默认**。目录解析优先级：

1. **用户自选目录**（记录在 `%APPDATA%/墨枢NovelAtlas/data-dir.json` 指针文件里）
2. **软件安装目录下的 `data/`**（默认，exe 同级；开发模式为项目根目录 `data/`，已加入 `.gitignore`）
3. **系统用户数据目录 `%APPDATA%/墨枢NovelAtlas/data`**（安装目录不可写时的自动兜底，设置页会提示）

变更目录时自动把旧目录的作品文件**复制**到新目录（不覆盖已有文件，旧目录原样保留）；首次从旧版本升级时，浏览器内置 IndexedDB 里的作品会一次性迁移进数据目录（非破坏性）。

- 实现链路：`electron/main.cjs`（目录解析 + 文件读写 IPC）→ `electron/preload.cjs`（`moshuDesktop.dataStorage` 桥）→ `src/core/storage/desktopAdapter.ts`（桌面端默认适配器）→ 设置页「数据存放位置」面板。
- Web 端仍是 IndexedDB / LocalStorage，文案保持「数据默认只存在你的浏览器里」不变——按端显示，互不干扰。

### 本地文件夹读写与实时同步（仅桌面端）

「导出中心」的整个文件夹一键导入、AI 上下文包直写、以及**本地文件夹双向同步**都依赖 File System Access API（`showDirectoryPicker`）：

- 桌面端（Electron，Chromium 内核）原生支持，目录句柄经 IndexedDB 持久化，可跨会话直写同一工作区目录；
- Web 版若浏览器不支持直写（如 Firefox/Safari），导入回退 `<input webkitdirectory>`、导出回退下载 ZIP；
- 「本地文件夹同步」面板按 `isDesktop()` 门控——**打包成网页时整块禁用**（避免 hosted 页面被误认为可后台读写本地盘）。

### 打包排错：`EPERM / EBUSY` 重命名 `win-unpacked.tmp`

现象：`npm run app:build` 在 electron 解压后报 `EPERM: ... rename 'win-unpacked.tmp' -> 'win-unpacked'` 或 `EBUSY: ... unlink '.../resources/default_app.asar'`。

根因：正打开本仓库的 IDE（VSCode/Qoder 等）文件监视器、或 Windows Defender 实时防护，在 electron 文件刚落盘时持有句柄，导致目录无法重命名/清理——**与代码、沙箱无关**（同目录做一次普通改名即可验证通过）。

解决（任选其一）：
- 把打包输出改到**工作区之外**：`npx electron-builder --win --config.directories.output=../skms-build`（IDE 不监视该目录，一次通过）；或长期把 `package.json` 的 `build.directories.output` 指向工程外；
- 关闭其它打开本仓库的 IDE，从**系统独立终端**跑 `npm run app:build`；
- 给 Windows Defender / 索引器添加对 `<项目>/release`（及 electron-builder 缓存目录）的排除项。

> 顺带：`author is missed in the package.json` 只是警告；要让安装信息显示发布者，在 `package.json` 顶层补 `"author": "…"`。
