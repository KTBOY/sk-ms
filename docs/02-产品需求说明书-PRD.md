# 产品需求说明书（PRD）

## 墨枢 NovelAtlas —— AI 小说创作一致性管理工作台

版本：v1.0　|　日期：2026-08-29　|　状态：定稿

---

## 1. 一句话定位

> **把小说的设定沉淀为知识图谱，在写作的每一步校验一致性，并把"恰好够用"的设定喂给 AI —— 让任何模型写长篇都不崩人设。**

墨枢不是 AI 写作器，而是 AI 写作的"场记 + 剧本监"：
- **写之前**：人物/事件/物品/地点/势力设计器沉淀世界观（结构化实体 + 关系 + 因果）。
- **写之时**：写作台实时对照图谱，谁对不上立刻提示；一键生成"上下文包"喂给任意 AI。
- **写之后**：全文一致性体检 + 主流格式导出（TXT/Markdown/DOCX/EPUB/JSON）。

## 2. 目标用户与画像

| 画像 | 场景 | 核心诉求 |
| --- | --- | --- |
| AI 网文作者 | 用 ChatGPT/DeepSeek 等长篇连载 | 设定不漂移，喂给 AI 的提示词一键可得 |
| 设定型作者 | 先建世界观再动笔 | 关系/因果可视化，随时查设定 |
| 同人/接单写手 | 多部作品并行 | 多作品管理，数据在本地，安全不外泄 |

## 3. 名词表

| 名词 | 定义 |
| --- | --- |
| 实体 | 人物 / 事件 / 物品 / 地点 / 势力的统称，有唯一 ID |
| 图谱 | 实体（节点）+ 关系/因果（边）构成的知识网络 |
| 上下文包 | 按当前章节自动汇集的实体设定 + 时间线 + 前情，可整体复制给 AI |
| 未登记名词 | 正文出现、但图谱中不存在的疑似专有名词 |
| 一致性体检 | 对全项目引用完整性、别名冲突、因果时序的自动检查 |

## 4. 功能需求

优先级：P0 = v1 必须；P1 = v1 尽量；P2 = 规划。

### 4.1 作品管理（P0）

- 多作品支持：新建（书名/题材/简介）、切换、重命名、删除。
- 首次进入自动载入示例作品《九州烟云》，用于演示全部功能。
- 全项目 JSON 备份导出 / 导入恢复。

### 4.2 人物设计器（P0）

字段：姓名、别名/称号（多个）、身份定位（主角/配角/反派/路人）、性别、年龄、所属势力、外观、性格、背景、目标动机、生死状态、自定义词条、五维能力（力量/智谋/魅力/意志/机缘，0–100，用于雷达图）、形象图（本地图片上传，压缩为 256px 内 base64 存储；无图时显示**白底剪影占位卡**）。

- 关系编辑：在人物详情内增删关系（目标人物 + 关系类型 + 强度 1–5 + 备注），关系类型预置：亲人/师徒/挚友/恋人/敌对/同门/上下级/自定义。
- 卡片墙视图 + 搜索 + 按定位/势力筛选；点击卡片进详情抽屉。

### 4.3 事件设计器（P0）

字段：事件名、时间标签（如"第三年春"）、排序序号（数值，驱动时间线/轨迹/事件图谱的横轴）、地点、参与人物（多选）、前因事件（多选）、后果事件（多选）、重要度（1–5）、所属章节、描述。

- 约束：参与人物、地点必须从图谱选择（见 4.6 联想与兜底）。
- 事件列表按排序序号排列；详情内可跳转关联事件。

### 4.4 物品 / 地点 / 势力设计器（P0）

- 物品：名称、别名、类型、稀有度、当前持有者（人物）、所在位置（地点）、来历、现状、描述。
- 地点：名称、别名、区域、上级地点、描述；详情显示辖内地点/事件/物品。
- 势力：名称、类型（宗门/王朝/组织/家族/其他）、首领（人物）、立场、描述；成员由人物表自动汇总。

### 4.5 时间线（P0）

- 全事件按排序序号纵向铺开的编年体视图；可按人物/势力过滤。
- 每个节点显示：时间标签、事件名、地点、参与人物头像组。

### 4.6 一致性引擎 ——"和图谱对不上"三层提示体系（P0，本产品灵魂）

用户输入的人物/事件与图谱对不上时，**必须立刻、可见、可操作地提示**。分三层：

**第一层：写作台实时识别（边写边提示）**
- 正文实时高亮已登记实体（人物紫、地点青、物品金、事件橙，玻璃质感标签样式）。
- 基于词频 + 停用词表的**未登记名词探测**：出现 ≥2 次、不在图谱、不在忽略词表的 2–4 字候选词，在右侧"一致性"面板以琥珀色警示卡列出：
  > ⚠ 图谱中未找到「赵管事」（出现 5 次）
  > 疑似输入：**赵管事**　|　你可能想写：**赵德海**（相似度 82%，或为别名/笔误）
  > 操作：`[设为人物]` `[登记为「赵德海」的别名]` `[加入忽略词表]`
- 预览模式中未登记名词显示琥珀虚线下划线，点击弹出同款操作气泡。

**第二层：表单引用联想（选人/选事件时的兜底）**
- 所有实体引用字段（参与人物、持有者、前因后果……）为联想选择器：输入即过滤（支持别名），失焦仍无匹配时字段下方出现琥珀提示：
  > 图谱中没有「xxx」，以免 AI 写崩，请选择已有实体或立即登记。
  > `[创建新实体]` `[改选相近项：xx、yy]`
- 明确**禁止**自由文本引用：自由文本 = AI 拿不到设定 = 写崩源头。

**第三层：全项目一致性体检（事后兜底）**
- 悬空引用：关系/事件参与者/持有者等指向已删除实体。
- 别名冲突：同一别名指向多个实体（AI 会混淆）。
- 因果时序：前因事件的排序号大于后果事件（时间倒挂）。
- 近名提醒：两个实体名相似度 ≥0.8（如 林霄/林啸），提示"考虑设置别名或改名"。
- 体检结果在总览页聚合展示（健康分），逐条可跳转修复。

### 4.7 写作台（P0）

- 左：章节列表（新增/上下移/删除，状态：草稿/写作中/已完成）。
- 中：章节标题 + 正文编辑（编辑/预览双模式）、字数统计、自动保存。
- 右：双页签
  - **一致性**：本章未登记名词卡 + 体检问题 + 已引用实体 chips（点击跳详情）。
  - **上下文**：上下文包预览 + `[复制上下文包]` + `[发送给 AI]`（已配置 AI 接口时）。
- 上下文包内容（结构化 Markdown）：作品一句话设定 → 本章大纲 → 出场人物卡（姓名/定位/性格/关系摘要）→ 相关地点/物品 → 本章涉及事件时间线 → 上一章梗概 → 写作要求（保持设定、不得引入未登记实体）。

### 4.8 D3 图谱中心（P0）

三个视图（页签切换）：

1. **关系图谱**：力导向图。节点 = 人物（大小按关系数、颜色按势力、金环 = 主角、灰环 = 已故）；边 = 关系（悬停显示类型标签，粗细按强度）。交互：拖拽、缩放、悬停高亮邻居、点击右侧详情卡（头像/势力/关系列表/参与事件，可跳编辑）。
2. **事件图谱**：横轴为时间序的因果网络。节点 = 事件（颜色按重要度），实线箭头 = 前因→后果，虚线 = 共享参与者（可开关）。
3. **人物轨迹**：选人物后，以时间为横轴渲染其一生的事件路径（折线 + 节点 + 地点标注），一眼看尽"此人经历"。

### 4.9 导出（P0）

| 格式 | 内容 | 说明 |
| --- | --- | --- |
| TXT | 正文连排 | 全平台通用 |
| Markdown | 卷/章标题 + 正文，可选附录·设定集 | 备份与再加工 |
| DOCX | 标题样式 + 章节 + 可选设定集 | 投稿/打印（docx 库生成） |
| EPUB | 章节 XHTML + 元数据 | 阅读/分发（JSZip 构建 EPUB3） |
| JSON | 全项目数据 | 备份迁移、接后端前的数据契约 |

### 4.10 设置（P0）

- **存储适配器**（见 §6）：本地 IndexedDB（默认）/ 本地 LocalStorage / REST API（预置）。
- REST 配置：Base URL、Token、作品 ID，`[测试连接]`；接口契约见 §6.2。
- AI 接口（预留）：OpenAI 兼容 Base URL / API Key / 模型名；配置后写作台可"发送给 AI"。
- 危险区：恢复示例数据、清空当前作品。

### 4.11 总览仪表盘（P0）

- 主角英雄卡：大形象图（无图则白底剪影）、五维雷达图、关键数据（出场章数/关系数/参与事件/提及次数）。
- 玻璃卡指标：总字数、人物数、事件数、待处理提示数（红点）。
- 最近事件流（对应参考图的 Games Stats 行卡样式）。
- 一致性体检摘要卡：问题分类计数，点击跳转处理。

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 架构 | 纯前端 SPA，无后端依赖；离线可用（除可选 AI 调用） |
| 技术栈 | Vite + React 18 + TypeScript(strict) + Zustand + D3 v7，无重型 UI 库，自研组件库 |
| 数据 | 本地优先；实体图片走 IndexedDB 友好格式（base64 压缩）；存储层接口化可替换 |
| 性能 | 10 万字正文内输入不掉帧（校验计算防抖 ≥300ms）；图谱 200 节点内流畅 |
| 可用性 | 全中文；危险操作二次确认；空态有引导；自动保存 |
| 兼容 | Chrome/Edge 最新两个大版本，1280px+ |

## 6. 存储与接口设计

### 6.1 适配器接口（代码即契约）

```ts
interface StorageAdapter {
  readonly id: 'indexeddb' | 'localstorage' | 'rest';
  readonly label: string;
  listProjects(): Promise<ProjectMeta[]>;
  loadProject(id: string): Promise<Project | null>;
  saveProject(project: Project): Promise<void>;
  deleteProject(id: string): Promise<void>;
}
```

适配器通过设置页切换；切换时提示先导出 JSON 备份。默认 IndexedDB（容量大，适合存人物形象图）。

### 6.2 预置 REST 契约（替换接口即可上云）

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `{base}/projects` | — | `{ projects: ProjectMeta[] }` |
| GET | `{base}/projects/:id` | — | `{ project: Project }` |
| PUT | `{base}/projects/:id` | `{ project: Project }` | `{ ok: true }` |
| DELETE | `{base}/projects/:id` | — | `{ ok: true }` |

鉴权：`Authorization: Bearer {token}`（可选）。前端已预置 `RestStorageAdapter`，填 Base URL 即接入。

## 7. 验收要点（v1）

1. 示例作品进入后，总览/图谱/写作台均有真实数据可玩。
2. 在写作台输入未登记名词，10 秒内能完成"发现 → 建为人物 → 高亮生效"闭环。
3. 事件表单选人物必须走联想器；对不上有兜底提示。
4. 关系/事件/轨迹三张 D3 图可交互（拖拽/缩放/点击详情）。
5. 五种导出格式逐一生成成功，EPUB 可被 Apple Books/Calibre 打开。
6. 刷新页面数据不丢；切换存储适配器后数据可迁移（导出/导入）。
