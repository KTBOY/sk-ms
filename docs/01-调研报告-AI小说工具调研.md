# AI 小说工具调研报告

> 项目：墨枢 NovelAtlas —— AI 小说创作一致性管理工作台
> 日期：2026-08-29
> 结论先行：**市场上"AI 生成小说"的工具很多，但"管理 AI 写小说所需的设定、防止 AI 写崩"的独立工作台是空白地带**。最接近的产品（Novelcrafter Codex）验证了这个方向的价值；本项目的差异化在于"图谱驱动 + 实时一致性校验 + 纯本地数据主权"。

---

## 1. 长篇 AI 写作的核心痛点

长篇小说用 AI 生成时，问题不是"写不出来"，而是"写崩"：

| 痛点 | 典型表现 |
| --- | --- |
| 设定漂移 | 第 10 章主角用的剑还是"青莲剑"，第 30 章变成了"青莲古剑"，第 50 章被 AI 忘记 |
| 人物 OOC | 配角的性格、口癖随生成漂移；已死亡的角色再度登场 |
| 关系错乱 | 师徒写成恋人、敌我阵营互换 |
| 时间线矛盾 | 事件的因果顺序颠倒、年龄对不上 |
| 重名混淆 | "林霄 / 林啸"这类近似名 AI 张冠李戴 |
| 上下文丢失 | 模型上下文窗口有限，前 50 章的伏笔根本装不进去 |

根因只有一个：**AI 每次生成只能看到塞进上下文的那一小段设定**。因此正确的产品形态不是"更强的生成器"，而是"**把设定管理好、并在恰当的时机把正确的设定喂给 AI**"。

## 2. 代表性产品分析

### 2.1 Novelcrafter（Codex / Story Bible）—— 方向最接近的标杆

- Codex 是一部"会说话的维基"：人物、地点、剧情线全部是**结构化条目**，直接作为 AI 上下文的数据源，而不是一段自由文本。
- 支持 Scene Beats（场景节拍）+ Codex 注入：写每一场戏时，把相关 Codex 条目按需注入提示词。
- 支持"Series entries"跨书共享设定，保持系列小说一致。
- 社区评价：功能强，但**配置繁琐**（条目触发词、注入策略都要手工调）。
- 启示：**"设定 = 结构化数据 = AI 上下文"** 这个三角关系是被验证的正确产品逻辑；我们要把"配置繁琐"这个缺点解决掉——用图谱自动关联、自动生成上下文包。

### 2.2 SillyTavern 世界书（World Info / Lorebook）—— 注入机制的教科书

- 机制：每条设定挂若干**触发关键词**，正文/对话中命中关键词才把该条设定注入上下文，可控制注入深度（绿灯/蓝灯、插入位置）。
- 优点：token 预算可控，按相关性注入。
- 缺点：触发词要手工设计；**写错了没有提示**——你把"林霄"写成"林啸"，世界书不命中，AI 悄悄地就把设定丢了，用户毫无感知。
- 启示：关键词触发是好的节能机制，但必须有"**对不上的兜底**"——这正是本产品"未登记名词提示 / 疑似笔误联想"设计的直接来源。

### 2.3 Sudowrite Story Bible —— 模板化设定的代表

- Braindump / Genre / Style / Characters / Worldbuilding / Outline 六段式设定，一键生成章节草稿时整体注入。
- 启示：设定模板要低门槛，先让作者"随便填"，再逐步结构化。

### 2.4 国内工具（笔灵、蛙蛙写作、彩云小梦、阅文系）

| 工具 | 定位 | 设定管理能力 |
| --- | --- | --- |
| 笔灵 AI 写作 | 网文全流程，300+ 生成器 | 有"设定集"（人物/金手指/势力/地点），但偏一次性生成，弱校验 |
| 蛙蛙写作 | 短篇快产、拆书、转剧本 | 大纲/情节生成强，设定管理弱 |
| 彩云小梦 | 续写互动 | 有"世界设定"，轻量，无图谱 |
| 阅文"妙笔"等 | 平台内辅助 | 封闭生态，不开放数据 |

共性：**重生成、轻管理；数据锁在平台里**。长文一致性的讨论（知乎/腾讯云开发者社区等）普遍指向"需要角色档案常驻 + 章节隔离 + 专项检阅"的工作台形态。

### 2.5 开源方案 NovelForge（GitHub）

面向百万字级长篇，集世界观构建与结构化生成于一体，明确以"长篇一致性"为卖点——证明该需求真实且未被满足。

## 4. 对本产品的结论与设计决策

1. **定位**：不做生成器，做"AI 小说的一致性中枢"——作者用什么 AI 都行，墨枢负责让 AI 不写崩。
2. **设定必须结构化**：人物/事件/物品/地点/势力是实体（有 ID、可关联），不是文档碎片；关系与因果显式建边，形成可交互的 D3 图谱。
3. **一致性要"前置提示"而不是"事后返工"**：写作时实时识别已登记实体与未登记名词；表单引用实体时自动联想，对不上立刻提示（详见 PRD 4.6"对不上"三层提示体系）。
4. **上下文包（Context Pack）是核心输出物**：一键把"本章涉及的人物卡/事件/时间线/上一章梗概"打包成结构化提示词，作者粘贴给任何 AI 使用；预留 OpenAI 兼容接口可直接调用。
5. **数据主权**：纯前端 + 本地存储（IndexedDB/LocalStorage），并提供**可插拔存储适配器**（预置 REST 接口，替换后无缝上云）。
